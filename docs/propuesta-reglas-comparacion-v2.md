# Propuesta técnica previa a implementación — 26 de octubre de 2026

Se conservan los cambios de comparación sin commit y el modelo v05 como referencia. Estado inicial de desarrollo: convocatorias.0001_initial aplicada.

1. Niveles admitidos: lista explícita `niveles_admitidos` dentro del contrato FORMACION. Se conserva `nivel_minimo` antiguo, sin derivar listas de él; ausencia de lista produce desconocido.
2. Misma formación: añadir a MAE_REQUISITO `relacion_formacion` (pendiente, independiente, misma_formacion) y `grupo_formacion` (clave legible dentro de la convocatoria). El valor inicial pendiente conserva la incertidumbre de relaciones antiguas. El administrador declara independencia o asigna la misma clave. Grupos solo académicos, con obligatoriedad coherente; se evalúan exclusivamente los miembros aplicables a la opción/destino actual. No se mezclan formaciones. Un grupo admite una candidata completa, conserva incertidumbre si alguna candidata no puede descartarse y falla solo si todas se descartan.
3. Equivalencias: lista estructurada `equivalencias` de cada requisito; no catálogo global sin contexto. Cada fila declara tipo (titulo/provincia/ciudad), origen, destino admitido, referencia a las bases y, para territorios, país y provincia cuando corresponda. Se valida contra los valores admitidos. Se reutilizan las rutas administrativas, permisos, revisión y auditoría existentes. Formulario de filas editables, sin JSON manual.
4. Destinos: FK opcional `destino` a CAT_PAIS en MAE_REQUISITO. Requiere opción de la misma convocatoria y país incluido en ella. NULL conserva ámbito común/opción existente. Evaluación separada por país: comunes + opción + condiciones de ese país. Agregación existencial entre destinos, nunca entre datos de formaciones. Destinos ausentes no se inventan. Movilidad solo con una regla TRASLADO explícita; modalidad virtual no la añade.
5. La lista de equivalencias vacía y los campos nulos son aditivos; no se convierten requisitos antiguos, títulos, territorios o mínimos a supuestos nuevos. Las escrituras y publicación revisan integridad; cambiar países no puede dejar requisitos de destino huérfanos.
6. Dedicación: perfil ambas satisface completa/parcial/ambas. En requisitos se conserva la pertenencia explícita; un requisito antiguo con valor ambas sigue exigiendo esa disponibilidad, no se transforma a completa o parcial.
7. Promedio: no se ha suministrado una fórmula concreta de conversión aprobada. Escalas diferentes siguen desconocidas. Experiencia: se registrará la convención literal y fecha de referencia; se filtrarán áreas y unirán intervalos superpuestos, limitando los actuales a la fecha publicada. No se inventará conversión a meses, por lo que el resultado seguirá pendiente mientras no exista una convención ejecutable aprobada. No se equiparan jornadas.
8. Resultados: mantener documentos pendientes, grupos académicos y desglose por destino. Destacar una opción coincidente o pendiente con texto comprensible, sin sugerir ranking. No persistir resultados ni crear las tablas TRA de IA.

Cambios físicos previstos: cuatro campos de MAE_REQUISITO y restricciones de coherencia mediante migración aditiva; contratos JSON ampliados, sin cambiar el JSON de requisitos almacenados. Actualizar diccionario y suplemento del modelo. Probar antes de aplicar a desarrollo.
